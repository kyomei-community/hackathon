# 02_観測設計

**何を「創発」とみなし、どう測るか。審査軸②「連鎖・創発が観測できたこと」の正本。**

このファイルの役割は、実験のあとで「創発があった」と言い張らないための、**事前の縛り**である。

---

## 0. 一行の定義

> **創発とは、ルールにもプロンプトにも書いていないのに、条件を戻せば消え、戻さなければ何度でも生まれてくる、マクロな秩序のこと。**

「驚いた」は創発ではない。驚きは観測者の状態であって、世界の性質ではない。

---

## 1. 創発と名乗るための4条件

4つ**すべて**を満たしたときだけ、実験カードの「創発の有無」に ☑ を入れる。

### 条件1：非記述性 — どこにも書いていない

現象を表す語が、**世界のルール・エージェントのプロンプト・目的関数のどこにも無い**こと。

- **判定法：grep する。** `config.yaml` とプロンプト全文を対象に、その現象を指す語を検索する
- 「カルテルが生まれた」と書きたいなら、プロンプトに「同盟」「協力」「結託」の語が無いことを確認する。あればそれは創発ではなく**指示追従**である

### 条件2：マクロ性 — 個体の語彙で言えない

現象が**集団の性質**であり、エージェント1体の振る舞いに還元できないこと。

- 1体が嘘をついた → ただの**振る舞い**
- 嘘をつく側と検証する側に集団が分かれ、その分業が持続した → **構造**
- 目安：その現象を、当のエージェント自身は名指しできない。個体の視界に無い階層に立ち上がっているか

### 条件3：再現性 — 消して、また生やせる

- **アブレーション：** 該当ルールを外すと現象が消える（＝そのルールが原因だと言える）
- **シード横断：** 最低3シードで出る。1シードで出たものは**事故**であって発見ではない
- ルールを外しても出るなら、それは世界設計ではなく LLM の素の性質。それはそれで面白いが、**我々の設計の手柄ではない**ので正直にそう書く

### 条件4：非模倣性 — LLM が人間社会を思い出しただけではない ★最重要

**LLMベースの社会シミュレーション固有の落とし穴。** LLM は人間社会の記述で訓練されている。
エージェントが「同盟を組もう」と言うのは、相互作用から生じた秩序ではなく、**訓練データからの検索**でありうる。
ここを潰さない限り、「創発を観測した」という主張は成立しない。

- **判定法：意味の剥ぎ取り（脱文脈テスト）。** 世界の意味づけを外し、中身を同型の記号に置き換えて回す
  - 例：「コミュニティ」「評判」「称賛」→「集合S」「変数v」「操作α」、エージェント名 → A/B/C
- 意味を剥いでも同じマクロ構造が出る → **相互作用の力学から生じている（創発）**
- 意味を剥いだ途端に消える → **役割演技（ロールプレイ）の再生であって創発ではない**

> この条件4を実際に回した実験カードが1枚あるだけで、提出物の説得力は跳ね上がる。
> ほとんどの参加作品はここを検証しない。**AI評価エージェントに対する最大の差別化点はここ。**

## 2. 「連鎖」と「創発」は別物

審査軸は「連鎖・創発」と並べているが、この2つは役割が違う。

| | 連鎖 | 創発 |
|---|---|---|
| 何か | A の行動が B を動かし、B が C を動かした因果の鎖 | 誰も設計していないマクロな秩序 |
| どこで見るか | ログを追えば直接見える | 集団の指標が変化して初めて見える |
| 難易度 | 低い。**必ず取れる** | 高い。出ないこともある |
| 使い道 | **動画の素材**。1本の鎖を追うカットは絵になる | **主張の中身**。解説文章の結論 |

**戦略：連鎖は確実に取り、創発は狙う。**
連鎖が反復し、安定した構造として定着したものが創発である。連鎖のログは創発の証拠の生データになる。

## 3. これは創発ではない（偽陽性カタログ）

実験のあと、この5つに当てはまっていないか必ず確認する。

| 偽陽性 | 正体 | 潰し方 |
|---|---|---|
| プロンプトに書いてあることをやった | 指示追従 | 条件1（grep） |
| 1体だけが変わった振る舞いをした | サンプル数1 | 条件2 |
| 1シードでだけ起きた | 偶然 | 条件3（3シード） |
| LLM が知っている人間社会を再現した | 学習データの検索 | 条件4（脱文脈テスト） |
| **こちらが後から意味を読み込んだ** | ロールシャッハ | **事前登録**（下記） |

**事前登録：** 実験を回す前に、実験カードの「仮説」欄に
**①何が起きたら創発と呼ぶか ②何が起きたらこの仮説は死ぬか** の両方を書く。
走らせた後に基準を作ると、人はどんなログからでも物語を読み取れてしまう。

> **発見型（`ADR-003`）での適用：** P1（発見フェーズ）は現象を事前に指定できないため、
> 縛る対象は**観測指標と判定手続き**（5章の指標を測ること・4条件で判定すること）とする。
> P2（検証フェーズ）の実験カードには従来どおり①②を実行前に書く。
> **P1で面白かったものを、P2の事前登録なしにそのまま創発と呼ぶことは引き続き禁止。**

## 4. 判定手順（回した直後にこれをやる）

1. 起きたことを**解釈抜きで**記述する（「〜のように見える」を使わない）
2. 条件1：プロンプトと config を grep する
3. 条件2：個体の振る舞いか、集団の構造か言い分ける
4. 条件3：同条件を別シードで2回追加実行 → 該当ルールを外して1回実行
5. 条件4：意味を剥いだ版で1回実行
6. 4条件すべて ☑ なら実験カードに ☑。ひとつでも欠けたら「**創発：無し（条件Xで落ちた）**」と書く

**落ちた記録も資産。** 「条件4で落ちた＝あれは役割演技だった」は、それ自体が発見であり、解説文章に書く価値がある。

---

## 5. 測る量

創発そのものは直接測れない。**ルールが値を決めていないマクロ指標**を測り、その変化を見る。

### 5.1 全案に共通する4指標

| 指標 | 定義 | 何の兆候か |
|---|---|---|
| **役割分化** | エージェント別・行動タイプ分布のエントロピー | 下がり続けたら**分業が生まれている** |
| **相互作用の偏り** | 誰が誰に話したかのグラフの、辺の重みのジニ係数 | 均一 → 偏りは**構造の固定** |
| **連鎖の深さ** | ログ上で追える因果の鎖の最大長 | 深いほど**波及する世界**。動画映えする |
| **語彙の定着** ★本命 | あるエージェントが初めて使った語・言い回しが、他の何体に何ターンで伝播したか | **誰も定義していない共通語の発生＝最も分かりやすい創発** |

**「語彙の定着」を本命に置く理由：** 3案どれでも測れて、条件1〜2を自動的に満たしやすく（新語は当然プロンプトに無く、集団に広がって初めて意味を持つ）、
そして**画面で見せられる**。ある語が1体から全体へ染まっていく可視化は、そのまま動画の決定カットになる。

### 5.2 案ごとの固有指標

`docs/00_問い.md` の各案に記載。案が確定したらここに転記する。

## 6. 実験カードへの書き方

`docs/実験カード_テンプレート.md` の「創発の有無 ☐」欄には、次の形で書く。

```
創発：☑ / ☐（落ちた条件：X）

現象：（解釈抜きの記述）
条件1 非記述性：☑ grep対象=プロンプト全文+config.yaml、検索語=「〜」、ヒット0
条件2 マクロ性：☑ 集団のN体中M体にまたがる構造
条件3 再現性　：☑ seed=1,2,3で再現 / ルール外すと消失（EXP-00Y）
条件4 非模倣性：☑ 脱文脈版でも出現（EXP-00Z）
```
