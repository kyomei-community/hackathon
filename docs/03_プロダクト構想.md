# 03_プロダクト構想

**誰の何に使えるか。審査軸③「プロダクト化への近さ」の正本。**
同時に、本プロジェクトのもうひとつの目的である **Kyomei の事業発展** への接続を管理する。

---

## 0. このプロジェクトは目的が2つある

| 線 | 目的 | 成功の定義 |
|---|---|---|
| **大会線** | ハッカソンで優勝する | 3審査軸すべてで上位。特に②を証拠で押し切る |
| **Kyomei線** | 事業を前に進める | 大会終了時点で、**Kyomei が翌週から使える資産**が手元にある |

**この2線を最後に合流させようとすると失敗する。**
「優勝してから事業転用を考える」は、転用可能な形で作っていないので転用できない。
逆に「事業のために作る」だけだと、問いが社内都合になり審査軸①が死ぬ。

**合流点は1つ、`docs/00_問い.md` の問いの選び方に置く。**
シミュレートする世界のルール変更が、**Kyomei が現実に直面している意思決定と同型**であるように問いを選ぶ。
そうすれば、審査軸③は後付けの作文ではなく実物になり、Kyomei線の資産は大会の副産物として自動的に手に入る。

---

## 1. プロダクト仮説：制度サンドボックス

> **「この制度・この仕様を入れたら、人の集団に何が起きるか」を、入れる前に試せる場所。**

社会シミュレーションを「面白い実験」で終わらせず、**意思決定の前工程**として位置づける。

- 制度やプラットフォーム仕様の変更は、入れてみるまで副作用が分からない。入れてからでは戻せない
- A/Bテストは「入れてから」しか測れない。**入れる前に副作用の形を見る**手段がない
- 本シミュレータは、ルールを1個差し替えると集団の振る舞いがどう変わるかを、
  連鎖グラフと4指標（`02_観測設計.md`）で出力する。**それがそのままプロダクトの中核機能**

大会の3案（`00_問い.md`）はいずれもこの形に乗る：
出所追跡を義務化したら／評価を相対評価にしたら／記録を各自に任せたら、集団に何が起きるか。

## 2. 誰の、どの意思決定に使うか — Kyomei / セカプラ

> 出典：セカプラ公式LP（https://lp.second-life-plus.com/）。本章の記載は公開情報の範囲に限る。

**セカプラ（Second Life+）**：50代からの人生を整える専門家伴走サービス（株式会社Kyomei）。
50〜60代女性向け・月額サブスク（Members 12,800円／Personal 39,800円・最低4ヶ月）。

**サービスの型は「知る → 実践する → 定着する」。** 差別化の核は"定着"であり、
公式に「セカプラが大切にしているのは、知識を届けることより、あなたの変化を定着させること」と掲げる。
定着を担う仕組みが ①習慣化プログラム（1〜3週間の伴走型）②会員コミュニティ（オープンチャット・
もくもく作業会）③専門家伴走 の3つ。

**課題表（サービス定義より）に「学んでも一人では行動・習慣化できない」が明記されている。**
そしてLPの中心主張は**「同じ価値観の仲間と続けられる」**——つまり、
**「コミュニティは継続を生む」という仮説の上にビジネスモデル全体が立っている。**

本シミュレータが検証するのはまさにこの仮説である（会話チャネル ON/OFF ＝ コミュニティ有無）。

**Kyomei が現実に迷える設計パラメータ**（＝サンドボックスの入力になるもの）

| パラメータ | 現実の選択肢 | 実験との対応 |
|---|---|---|
| コミュニティの相互作用をどこまで開くか | オープンチャットの範囲・可視性 | 会話チャネル ON/OFF（EXP-001〜006） |
| 習慣化プログラムの伴走期間 | 1週間か3週間か、その後どう手を離すか | 発見された維持要因の減衰実験（拡張） |
| 何を可視化するか | 他会員の実践・報告をどこまで見せるか | 発見された要因のアブレーション（拡張） |

**4ヶ月の最低契約期間は「変化の定着に必要な期間」として設定されている。**
定着の要因が実験で特定できれば、この期間設計・プログラム設計に直接根拠を与える。

## 3. 審査軸③で何を見せるか

「事業計画を語る」ではなく、**動くものを見せる**。デモの形は次の一本道に固定する。

1. 現実の制度・仕様を1つ入力する
2. ルールを差し替えて回す
3. 「導入前／導入後」で集団の指標が変わるところを、**同じ画面で並べて**見せる
4. 「この副作用は設計されていなかった」と言い切る

この4カットが成立していれば、③は口頭説明なしで伝わる。
**逆に、この4カットが作れない問いは選ばない。**

## 4. 大会後の接続（主催者が明示している出口）

本大会は終了後の支援を用意している。**これは Kyomei線の実質的な事業開発チャネル。**

| 出口 | Kyomei にとっての意味 |
|---|---|
| 企業・大学と連携した事業化支援 | 提携先探索のコストをかけずに接点が持てる |
| デジタルハリウッド大学／シンギュラボ専門家による論文化支援 | `02_観測設計.md` の4条件を満たした検証は**そのまま論文の骨格になる**。技術的信用の獲得 |
| 優秀作品への GPU ワークステーション貸与 | 継続開発の計算資源。API課金の制約から抜けられる |

**したがって「優勝」は目的ではなく、この3つの出口を開けるための手段である。**
提出物は「審査員に勝つ」だけでなく「**この3つの相手に見せられる**」水準で作る。

## 5. Kyomei に残す成果物（大会提出物とは別に確保する）

大会に出すもの（コード・動画・解説文章）とは別に、Kyomei線の資産を明示的に残す。

- [ ] **制度サンドボックスの再利用可能な形** — ルール差し替えのインターフェースが、大会の3案以外にも開いていること
- [ ] **Kyomei の実ケースを1件通した記録** — 【要確認】が埋まり次第、実験カード1枚として実施
- [ ] **対外資料** — 受賞歴の有無にかかわらず、動画と解説文章はそのまま営業・採用の素材にする
